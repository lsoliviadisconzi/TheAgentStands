# TheAgentStands — Reel Manager

A studio-style editor for creating narrated vertical reels (TikTok/Reels/Shorts format) with theme-based animated players, TTS narration generation, and MP4 export.

---

## Quick Start

```bash
# Install dependencies
pnpm install

# Start backend (port 4000)
cd backend && pnpm run dev

# Start frontend (port 5173)
cd ../frontend && pnpm run dev
```

Open http://localhost:5173 in your browser.

## Data Directory (`data/`)

The `data/` directory is **runtime-only** and should be **gitignored**. All files here are generated or uploaded at runtime.

### `data/reels.json`
**Primary persistence** for all user reels. Created/updated by:
- **Create new reel** → POST `/api/reels`
- **Import from theme** → POST `/api/reels/import`
- **Import from narrations** → POST `/api/reels/import-narration`
- **Autosave** (debounced 500ms) → PUT `/api/reels/:id`
- **Toggle landing** → PUT `/api/reels/:id` with `{ onLanding }`
- **Reorder** → PUT `/api/reels/:id` with `{ order }`

**Format:** Array of `Reel` objects (see `backend/src/model.ts` for interface).

### `data/audio/{reelId}/`
**Generated TTS narration files.** One MP3 per line.
- **Created by:** POST `/api/reels/:id/lines/:lineId/tts`
- **Naming:** `{lineId}-{key}.mp3` where `key = SHA1(text|voiceId)[:10]`
- **Cleanup:** Old audio files deleted when line is regenerated or deleted
- **Stale detection:** Frontend compares `line.audio.key` with `SHA1(line.s|line.voiceId)`

### `data/cover/`
**Cover images** for reels.
- **Auto-generated:** First frame of exported video → `{reelId}_auto.jpg`
- **Manual upload:** POST `/api/reels/:id/cover` → `cover/{random}.jpg`
- **Usage:** Displayed in library, used as video poster

### `data/video/`
**Exported MP4 files.**
- **Created by:** POST `/api/reels/:id/export` (async, polls GET `/api/reels/:id/export`)
- **Naming:** `{reelId}.mp4`
- **Rendered via:** Playwright capturing the theme player at 2x scale (720×1280)

### `data/music/{reelId}/`
**Background music tracks** (optional).
- **Upload:** POST `/api/reels/:id/music` (multipart)
- **Volume:** Adjusted in editor (0–1), mixed during export
- **Format:** Any audio format supported by browser/FFmpeg

### `data/narrations/`
**Source narration content** — structured JSON for importing pre-written reels.
**This directory is NOT generated by the app.** It is populated externally (see below).

#### Structure
```
data/narrations/
├── index.json                              # Master theme index
├── {theme-slug}/
│   ├── index.json                          # Theme metadata + languages
│   └── {language}/
│       ├── index.json                      # Language metadata + reel list
│       └── {reel-slug}.json                # Full narration (scenes, text, moods)
```

#### File Formats

**`index.json` (master)**
```json
{
  "themes": {
    "the-denial-came-first": {
      "title": "The Denial Came First",
      "languages": ["en", "it", "de", "pl", "sr-Latn", "fr", "es", "pt-BR"]
    }
  }
}
```

**`{theme-slug}/index.json`**
```json
{
  "theme": "the-denial-came-first",
  "title": "The Denial Came First",
  "languages": {
    "en": { "code": "en", "label": "English", "reelCount": 5 },
    "it": { "code": "it", "label": "Italiano", "reelCount": 5 }
  }
}
```

**`{theme-slug}/{language}/index.json`**
```json
{
  "theme": "the-denial-came-first",
  "language": "en",
  "reels": [
    { "slug": "nobody-asked", "title": "Nobody Asked", "hook": "Nobody asked...", "sceneCount": 3 }
  ]
}
```

**`{theme-slug}/{language}/{reel-slug}.json`**
```json
{
  "theme": "the-denial-came-first",
  "language": "en",
  "reel": "nobody-asked",
  "title": "Nobody Asked",
  "hook": "Nobody asked. They answered anyway.",
  "stamp": "The denial arrived before the question.",
  "next": "Next: out of jurisdiction.",
  "scenes": [
    {
      "index": 0,
      "direction": "reading a statement nobody requested",
      "text": "Nobody asked whether we ignored the complaint...",
      "mood": "flat",
      "panel": ["question_asked = none", "denial_issued = yes"],
      "holdMs": 1300
    }
  ]
}
```

#### How to Populate Narrations

**Option 1: Manual creation**
Create the JSON files by hand following the structure above.

**Option 2: Migration from HTML themes (legacy)**
The old theme HTML files (`themes/{Theme}/{Theme} - {lang}.html`) contain a `const R = [...]` array with reel data. A one-time migration script can extract this into the narrations JSON structure. See `create_translations.py` and related scripts in the repo root.

**Option 3: External translation pipeline**
The narration JSON is designed to be produced by an external content/translation pipeline (e.g., CMS, spreadsheet, translation memory). The app only **consumes** it via the import endpoint:
```
POST /api/reels/import-narration
{ "themeSlug": "...", "language": "...", "reelSlug": "..." }
```

#### Slug Rules
- **Theme slug:** lowercase, spaces→hyphens, remove special chars
- **Reel slug:** lowercase, spaces→hyphens, remove special chars, max 50 chars

## Resetting / Cleaning Data

### Full Reset (Nuclear Option)
```bash
# Stop servers first!
rm -rf data/
mkdir -p data/audio data/cover data/video data/music data/narrations
# Note: narrations/ must be repopulated from source if needed
```

### Selective Cleanup

| Target | Command | Effect |
|--------|---------|--------|
| All reels + generated media | `rm -rf data/reels.json data/audio data/cover data/video data/music` | Removes all user reels, audio, covers, videos, music. Keeps narrations. |
| Only generated audio | `rm -rf data/audio/*` | Forces re-generation of all narration |
| Only exported videos | `rm -rf data/video/*` | Removes MP4s, keeps covers |
| Only covers | `rm -rf data/cover/*` | Removes cover images (auto + manual) |
| Only music | `rm -rf data/music/*` | Removes background tracks |
| Single reel | Delete via UI, or: `rm -rf data/audio/{reelId} data/video/{reelId}.mp4 data/cover/{reelId}*` then remove from `reels.json` | Clean removal of one reel |

> **Tip:** The backend `removeReel()` function (DELETE `/api/reels/:id`) handles all associated file cleanup automatically. Prefer using the API/UI.

## How Data Files Are Used

### At Runtime

| File | Read By | Written By |
|------|---------|------------|
| `reels.json` | All reel endpoints (GET, PUT, DELETE) | POST/PUT/DELETE `/api/reels*` |
| `audio/{reelId}/*.mp3` | Preview player, export renderer | TTS endpoint |
| `cover/*` | Library thumbnails, video poster | Cover upload, auto-poster from export |
| `video/{reelId}.mp4` | Landing page, "Open MP4" link | Export endpoint |
| `music/{reelId}/*` | Preview player (volume), export mixer | Music upload |
| `narrations/**/*.json` | Narration browser (left drawer) | **External only** (read-only at runtime) |

### Theme System

Two theme systems coexist:

1. **Legacy HTML themes** (`themes/`) — Used for import only. Each file contains `const R = [...]` with reel templates. The app parses these to create new reels.

2. **Narrations JSON** (`data/narrations/`) — Modern structured format with full multi-language support. Preferred for new content.

## Key Architecture Notes

- **Single-writer store:** `reels.json` is read→mutated→written synchronously per request (no concurrent write issues).
- **Never hold Reel across await:** Always re-read with `updateReel()` after async operations.
- **Plan = Preview = Export:** The `planReel()` function drives the theme player's `h` (hold) values so timeline, live preview, and exported video all match.
- **Offsets stretch previous hold:** A line's `offset` ("start no earlier than") is implemented by extending the previous line's hold. First line cannot be offset (fixed hook card).
- **Stale audio detection:** Frontend and backend both compute `SHA1(text|voiceId)` to detect when narration needs regeneration.
